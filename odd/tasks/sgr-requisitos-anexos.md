# SGR: requisitos habilitantes, aval institucional, licencias y anexos (plan P6)

Objective: give the SGR flow a checklist of the call's enabling requirements (Conv 54 numeral 11, Conv 56 numeral 10) and of the institutional endorsement documents (UNAL VRI procedure), the figure-coherence check across SIGP, Anexo 1, Anexo 3 and MGA Web, and the two Anexo 2 chapters Morfeo still lacks (cap. 28 «Análisis de licencias y permisos», cap. 31 «Anexos»), with a pipeline unit and a dashboard tab where the user marks each requirement. SGR-only; the base flow does not change.
Branch `feat/sgr-requisitos-anexos` (stacked on `feat/sgr-productos-indicadores`), delivery `single-pr`. Tests: `uv run python -m unittest discover tests -p "test_*.py"` and the JS suite (scratch jsdom). Receipt-driven review is off for this clone.

## Contracts

Rubric `requisitos` (each call file): `[{id:"11.4", nombre, texto, condicion:null|"etica"|"internacional"|"sector_productivo"|"sociedad_civil"|"infraestructura"|"inmuebles"|"cofinanciacion"|"desastre"|"otro", documento, numeral_fuente}]`. `nombre` and `texto` are verbatim TdR fragments (the requirement title and its first sentence or the sentence that names the document); `documento` names what is attached (e.g. «Anexo 1», «Carta de intención», «MGA Web Tipología D – PIIP»); `condicion` is set only when the TdR marks the requirement as conditional.

`scripts/rubricas_sgr/_aval_institucional.json`, schema `morfeo.aval-institucional/v1`: `{schema, instituciones:[{id:"unal", nombre, patron_nombre, fuente, convocatorias:["conv54","conv55"], documentos:[{indice, texto}], hitos:[{actividad, responsable, fecha:"YYYY-MM-DD", fecha_texto}]}]}`; `texto`, `actividad`, `responsable` and `fecha_texto` verbatim from the VRI procedure.

`artefactos/sgr/requisitos.json`, schema `morfeo.requisitos-sgr/v1`:
```
{schema, convocatoria:"conv54"|"conv56"|null,
 items:[{id:"11.4", estado:"pendiente"|"en_tramite"|"listo"|"no_aplica", responsable:"E1"|null,
         archivo:str|null, fecha:"YYYY-MM-DD"|null, nota:str|null, justificacion:str|null}],
 cifras:{sigp:{total_sgr, total_contrapartida, total}|null,
         anexo1:{por_entidad:{"E1":{especie, efectivo}}}|null,
         anexo3:{total_sgr, total_contrapartida, total}|null,
         mga:{total_sgr, total}|null},
 licencias:{introduccion, items:[{licencia, norma, aplica:bool, justificacion, responsable:"E1"|null,
            momento:"previo"|"ejecucion"}]}|null,
 aval_institucional:{institucion:"unal"|null, documentos:[{indice, estado, archivo|null}]}|null}
```
`archivo` is a path relative to the run root (normally under `insumos/requisitos/`).

Rules (`check`, findings `{severity, code, message, node}`, codes `requisitos-*`): every rubric requirement has an item (missing → warning; `init` adds it); unknown ids → error; valid enums; `no_aplica` needs a `justificacion` (error) and is allowed only for requirements with a `condicion` (error otherwise); a derived condition that applies but whose item is `no_aplica` → error: `internacional` applies when an alliance entity has `tipo` «internacional», `sector_productivo` when one has `tipo` «sector_productivo», `infraestructura` when the budget has SGR money in the `infraestructura` rubro, `cofinanciacion` when an entity that is not the proponent declares `aporte_efectivo` > 0; the other conditions are not derived; an item `listo` with an `archivo` that does not exist on disk → error, `listo` without `archivo` → warning; responsible ids exist in `alianza.json`; figures: each declared `cifras` value equals the budget summary (`presupuesto_sgr.py resumen`: total_sgr, especie + efectivo as contrapartida, total) and, for `anexo1.por_entidad`, the entity's `aporte_especie` / `aporte_efectivo` in `alianza.json` (error on mismatch beyond 1 peso; undeclared → info); licences: each item with `aplica` true needs norma, responsable and momento (error), `aplica` false needs justificacion (error), no licences block → warning; endorsement: when the proponent's name matches an institution's `patron_nombre` and the call is in its `convocatorias`, each of its documents has an entry (warning when missing). `--final`: applicable items not `listo` → error. `vista RUN` → `{convocatoria, requisitos:[rubric fields + item fields + aplica_derivada:bool|null], progreso:{listos, aplicables}, cifras:[{documento, campo, declarado, esperado, coincide}], licencias, aval:{institucion, documentos, hitos}, findings}`; works when `requisitos.json` is missing (items read as `pendiente`). `actualizar_item(run, id, cambios)` validates the id and each field (only `estado`, `responsable`, `archivo`, `fecha`, `nota`, `justificacion`), creates the file through `init` when missing, writes atomically and returns the updated item; the same function with id `cifras.<documento>` replaces one declared figures block. `datos RUN --json`: `{requisitos:{aplicables, listos, pendientes:[ids], no_aplica:[ids]}, cifras_coherentes:bool|null, fuente}`.
